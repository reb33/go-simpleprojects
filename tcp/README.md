### tcp
 1. Текстовые протоколы (Уровень «Основы»)
	•	Чат-комната с никнеймами:
	◦	    Клиент: При запуске спрашивает имя, затем отправляет текстовые сообщения. Принимает сообщения от других и выводит в консоль.
	◦	    Сервер: Регистрирует пользователей, рассылает сообщения всем, кроме отправителя. Обрабатывает команду /quit.
	•	Удаленное управление (Командная строка):
	◦	    Клиент: Отправляет системные команды (например, ls, pwd, ping).
	◦	    Сервер: Выполняет эти команды в ОС и возвращает клиенту стандартный вывод (stdout).

2. Бинарные данные и файлы (Уровень «Продвинутый»)
	•	Загрузчик файлов с прогресс-баром:
	◦	    Клиент: Отправляет имя файла, его размер (8 байт) и сам файл кусками (чанками). Отображает прогресс в процентах.
	◦	    Сервер: Считывает размер, создает файл на диске и записывает входящий поток строго до указанного размера.
	•	Мониторинг ресурсов (Метрики):
	◦	    Клиент: Раз в секунду собирает загрузку CPU и RAM, пакует в бинарную структуру (например, через encoding/binary) и шлет на сервер.
	◦	    Сервер: Принимает структуру, логирует показатели с меткой времени.

3. Сетевая логика и стабильность (Уровень «Профи»)
	•	Аутентификация + Сессии:
	◦	    Клиент: Сначала шлет токен или пароль. Если сервер одобряет — переходит в режим обмена данными.
	◦	    Сервер: Хранит список активных сессий. Без авторизационного пакета сбрасывает соединение.
	•	Устойчивое TLS-соединение:
	◦	    Клиент и Сервер: Обмениваются данными не через сырой TCP, а поверх шифрования (задачи на генерацию самоподписанных сертификатов и использование пакета crypto/tls).

### tcp сервер
#### Базовый уровень
	1.	Эхо-сервер: Сервер принимает текст и возвращает его обратно клиенту.
	2.	Калькулятор: Клиент отправляет строку вида 5 + 10, сервер возвращает 15.
	3.	Узнай время: Сервер отправляет текущее время при подключении и закрывает соединение.
	4.	Генератор цитат: При подключении сервер выдает случайную фразу из массива.

#### Средний уровень
	5.	Многопользовательский чат: Сервер транслирует сообщения одного клиента всем остальным подключенным пользователям.
	6.	Хранилище Key-Value: Клиент может отправлять команды SET key value и GET key.
	7.	Передача файлов: Клиент отправляет файл byte-by-byte, сервер сохраняет его на диск.
	8.	Ограничитель частоты (Rate Limiter): Сервер сбрасывает соединение, если клиент шлет больше 5 запросов в секунду.

#### Продвинутый уровень
	9.	Собственный протокол: Сервер парсит кастомный бинарный формат (например: 2 байта — длина, 1 байт — тип команды, далее — полезная нагрузка).
	10.	Heartbeat / Ping-Pong: Сервер раз в 10 секунд проверяет активность клиента и отключает «мертвые» сессии.
	11.	Прокси-сервер: TCP-сервер принимает запрос и перенаправляет его на другой сервер, возвращая ответ обратно.
	12.	Сервер с Graceful Shutdown: Сервер корректно завершает работу, дожидаясь обработки всех текущих соединений перед закрытием.
