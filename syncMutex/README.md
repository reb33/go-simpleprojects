### Задание 1. Счетчик активных TCP-подключений (Легкое)
Контекст: Вы пишете TCP-сервер. Вам нужно в реальном времени знать, сколько клиентов сейчас подключено, чтобы не превысить лимит сервера.

	•	Задача: Создайте структуру ConnectionCounter. Реализуйте в ней три метода: Increment() (вызывается при подключении клиента), Decrement() (вызывается при отключении) и Count() int (возвращает текущее число).
	•	Условие: Запустите в main 1000 горутин, каждая из которых симулирует подключение (вызывает Increment, спит 10 миллисекунд, затем вызывает Decrement).
	•	Что проверить: Без мьютекса счетчик уйдет в data race и итоговый результат после завершения всех горутин не будет равен 0. С sync.Mutex значение в конце должно строго равняться нулю.
### Задание 2. Потокобезопасный пул TCP-соединений (Среднее)
Контекст: В сетевых программах часто нужно хранить список всех активных клиентов (например, чтобы реализовать чат и рассылать всем сообщения). Обычная карта map в Go не защищена от конкурентной записи и упадет с паникой.

	•	Задача: Реализуйте структуру SessionManager, которая внутри хранит map[string]net.Conn (где ключ — ID пользователя, а значение — его сетевое соединение).
	•	Методы:
	1	AddSession(id string, conn net.Conn) — добавляет клиента.
	2	RemoveSession(id string) — удаляет клиента.
	3	Broadcast(msg []byte) — отправляет сообщение всем клиентам из карты.
	•	
	•	Условие: Напишите тест или симуляцию в main, где одни горутины постоянно добавляют и удаляют случайных пользователей, а другие параллельно пытаются вызвать Broadcast для отправки сообщений. Защитите карту с помощью sync.Mutex.
### Задание 3. Защита от дублирования сетевых запросов (Сложное)
Контекст: Паттерн называется Singleflight. Представьте, что 100 клиентов одновременно запросили у вашего сервера «тяжелую» статистику, которой еще нет в кэше. Вместо того чтобы делать 100 тяжелых запросов в базу данных или к другому серверу, нужно сделать только один, а остальным 99 подождать и вернуть тот же самый результат.

	•	Задача: Напишите структуру RequestTracker. У нее должен быть метод Do(key string, fn func() string) string.
	•	Логика работы: Если метод Do вызывается с ключом, который прямо сейчас уже обрабатывается другой горутиной, текущая горутина не должна запускать функцию fn. Она должна дождаться, пока первая горутина завершит выполнение fn, и вернуть тот же самый результат.
	•	Подсказка: Вам понадобится sync.Mutex для защиты карты текущих запросов, а также каналы chan или sync.WaitGroup внутри структуры запроса, чтобы заставить другие горутины ждать окончания первого вызова.
